# Random Long String Generator (Docker-deployable)

**English** | [中文](README.zh-CN.md)

A web page that generates cryptographically secure random long strings, with a JSON API. **Zero npm dependencies**, tiny image, one-command Docker deployment.

> ## ⚠️ Security Warning
>
> - **Do not use over untrusted networks/pages**: when accessed over plain HTTP on the public internet, generated strings may be intercepted or tampered with by a man-in-the-middle. Always serve it over HTTPS (reverse proxy).
> - **Do not use it to generate real passwords / long-term keys**: strings generated by a web page are not suitable as real account passwords or long-term encryption keys. Use a dedicated password manager (Bitwarden, KeePass, etc.) or local commands (e.g. `openssl rand -base64 32`) for real credentials, and store them securely.
> - **This tool is open source, provided "as is"**: although the randomness comes from the OS cryptographic random source (Web Crypto / `crypto.randomBytes`), the author makes no warranty about the security of generated content.
> - See [SECURITY.md](SECURITY.md) for details. Report security vulnerabilities through the private channel — **do not disclose them in public issues**.

## ✨ Features

- Generate random strings from **1 to 1,000,000** characters long
- Selectable charsets: lowercase / uppercase / digits / special symbols / custom characters
- Batch generation up to 100 strings at once, one per line
- One-click copy, history (click an entry to copy)
- Based on browser `crypto.getRandomValues` (cryptographically secure), rejection sampling removes modulo bias
- Built-in REST API for scripting
- Nothing generated is saved on the server; the server only serves the static page

## 🌐 Languages

The UI is **English by default** with a **language toggle button** (top-right corner) to switch between English and Chinese. The choice is remembered in your browser (localStorage).

## 🐳 Docker Deployment (recommended)

### Option 1: docker compose

```bash
cd random-string-gen
docker compose up -d --build
```

### Option 2: docker build directly

```bash
docker build -t random-string-gen .
docker run -d --name random-string-gen -p 3000:3000 --restart unless-stopped random-string-gen
```

Then visit: **http://localhost:3000**

> Changing the host port: change the left side of `-p 3000:3000` or `"3000:3000"` in compose, e.g. `"8080:3000"`.

### Stop / remove

```bash
docker compose down          # stop and remove the container
docker rmi random-string-gen # remove the image
```

## 🖥 Run locally (no Docker needed)

Requires Node.js 18+:

```bash
node server.js
# or with a custom port
PORT=8080 node server.js
```

## 📡 API

```
GET /api/random?len=64&charset=base62&count=3
```

| Param | Description | Default |
|---|---|---|
| `len` | String length (1 ~ 1,000,000) | 64 |
| `count` | Number of strings (1 ~ 100) | 1 |
| `charset` | `hex` / `base62` / `base64` / `alnum`, or any custom string | base62 |

Examples:

```bash
# 64-char hex string
curl "http://localhost:3000/api/random?len=64&charset=hex"

# 5 strings of 32 chars base62
curl "http://localhost:3000/api/random?len=32&count=5"

# custom charset
curl "http://localhost:3000/api/random?len=20&charset=abcdefghij123456"
```

JSON response:

```json
{
  "ok": true,
  "length": 32,
  "count": 5,
  "charsetSize": 62,
  "strings": ["..."],
  "generatedAt": "2026-01-01T00:00:00.000Z"
}
```

Health check: `GET /api/health` (used automatically by the Docker image's HEALTHCHECK).

## 🔒 Security notes

- Randomness source: browser-side `crypto.getRandomValues`, server-side `crypto.randomBytes` — both are OS-provided cryptographically secure random sources
- **Rejection sampling** is used to remove modulo bias, guaranteeing each character is equally likely
- Runs as a non-root user inside the container
- Generated content is never saved on the server; frontend generation makes no network requests
- **Always use HTTPS when deploying publicly** to avoid the strings being transmitted in plaintext
- Vulnerability reporting and full security policy: see [SECURITY.md](SECURITY.md) (MIT license: see [LICENSE](LICENSE))
